# Phase 0 통합 리서치 (2026-07-28)

조사 방법: 병렬 에이전트 3개 (①보유 하드웨어 전수조사 ②e-ink 터미널 오픈소스 ③Claude Code 씬클라이언트) + 외부 제안 4안 검증 + Threads 사례 1건.

## 1. 대전제 판정

- **VS Code GUI → e-ink: 불가.** vscode.dev/code serve-web/tunnel 모두 모던 브라우저 필수. ESP32엔 브라우저가 없고, e-ink 태블릿 구형 브라우저에서도 비실용.
- **Claude Code(터미널 CLI) → e-ink: 가능.** 텍스트 스트림이므로 ①미러링 ②SSH 직결 ③질문-응답 API 세 갈래 전부 성립.
- "Claude Code × e-ink" 정면 승부 선례는 거의 없음 → 완성하면 공개 가치 있음.

## 4. 제약 사항 (설계에 박아야 할 것)

1. **ESP32-C3/S3 = BLE 전용** (클래식 BT 없음) → BLE(HOGP) 키보드만. 단 Good Display 데모보드(ESP32-D0WD)는 듀얼모드라 클래식도 가능.
2. **C3 = RAM 380KB·PSRAM 없음** → SSH+TLS+BLE 동시 구동은 타이트. 미러 방식이 안전한 이유.
3. **e-ink 갱신**: X4 풀 리프레시 ~1.7초(xteink-terminal 실측) → 실시간 스크롤 불가. **변경 라인만 부분갱신 + 단어 단위 출력 버퍼링**(reMarkable 사례)으로 흡수.
4. ESP32용 **mosh 포팅은 없음** → ESP32 직결은 SSH 또는 HTTP 폴링뿐. mosh가 필요하면 Pi 트랙(D5)뿐.
5. Wi-Fi/BLE **안테나 공유** (C3 단일 라디오) → 동시 사용 시 중재 필요 (biscuit RadioManager 방식).
6. 외부망에서 ESP32는 Tailscale 불가 → Cloudflare Tunnel + 기기 비밀키 (cardputer-relay 패턴).
7. 이미지 폴링 시 PNG 디코드는 PSRAM 요구 → **1-bit BMP** 또는 텍스트 프레임 사용.

## 6. 외부 제안 4안 검증 결과 (요약)

- ① Cardputer SSH: **기각** — 보유기는 Adv(키보드 I2C)라 원판용 레포 비호환 (D4)
- ② Pi+PaperTTY: **보험 보류** — 유일한 구매 트랙, 가장 확실하지만 보유기기 우선 (D5)
- ③ 서버렌더+ESP32 뷰어: **채택(수정)** — 패널은 T03이 아니라 GDEY042T81(부분 0.39초)로, Phase 2에 흡수
- ④ X4 네이티브 SSH: **Phase 3로 채택** — 단 xteink-terminal 디딤돌을 먼저
